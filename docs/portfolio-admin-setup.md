## 로컬 설정과 빌드

Node.js 24를 사용합니다. 의존성은 잠금 파일 기준으로 설치합니다.

```powershell
npm ci
Copy-Item .env.example .env.local
```

이미 `.env.local`이 있으면 덮어쓰지 말고 필요한 값을 확인합니다.

```dotenv
VITE_SUPABASE_URL=https://fslymhrfkcmetxdnzxxw.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=프로젝트의_sb_publishable_키
```

`.env.local`은 Git에서 제외합니다. publishable key는 브라우저에 포함되는 공개 연결 키이며, 데이터 접근은 인증과 RLS로 제한합니다. 서버 전용 `sb_secret_` 또는 service-role key를 넣지 마세요. 배포 전 검사 스크립트는 Supabase HTTPS 주소와 `sb_publishable_` 키 형식을 확인합니다.

```powershell
npm test
npm run lint
npm run build
npm run build:admin
```

공개 빌드는 `dist/`, 관리자 빌드는 `dist-admin/`입니다. 관리자 빌드는 공개 폴더 전체를 복사하지 않고 필요한 로고·파비콘과 `_headers`를 추가하며, 공개 사이트의 `CNAME`을 포함하지 않습니다. `npm run dev:admin`은 5176 포트에서 관리자 개발 화면을 엽니다.

## 데이터베이스와 저장소 권한

`supabase/migrations/202610150001_portfolio.sql`과 `supabase/grant-initial-admin.sql`은 현재 클라우드에 적용되어 있습니다. 기존 프로젝트에 다시 실행하지 마세요. 테이블·정책·함수를 새로 만드는 초기 마이그레이션이므로 재실행을 전제로 하지 않습니다. 변경이 필요하면 현재 스키마를 확인하고 별도의 후속 마이그레이션을 작성합니다.

`supabase/migrations/202610150002_photo_descriptions.sql`도 현재 클라우드에 적용되어 있습니다. `valid_portfolio_images` 검증 함수에 선택적인 사진 부연설명 문자열과 2,000자 제한을 추가합니다. 기존 사진처럼 부연설명 필드가 없는 데이터도 허용합니다. 현재 환경에는 다시 적용할 필요가 없습니다. 새 환경에서는 001 다음에 002를 순서대로 적용합니다.

`supabase/migrations/202610150003_homepage_hero.sql`은 2026-10-15 클라우드에 적용했습니다. `homepage_hero`의 `main` 단일 설정과 기존 사진 4장 초기값, 관리자 수정 정책과 저장소 사진 참조 보호를 추가합니다. 현재 환경에서 003을 다시 실행하지 마세요. 새 환경에서는 001·002·003을 순서대로 한 번씩 적용합니다.

기존 공개 사례는 이전 제목과 위치가 일치하는 조건으로 공개 제목을 ‘아파트 인테리어’로 변경하고 위치를 비웠습니다. 공개 API에서 변경된 제목·빈 위치·사진 4장 보존을 확인했습니다. 앞으로 관리자 화면은 주소 없는 공개 제목을 안내하고 위치 입력을 받지 않으며, 저장 payload는 위치를 빈 값으로 보냅니다. 제목 일반화는 입력 안내이므로 새 사례 공개 전 실제 제목에 주소 정보가 없는지 확인합니다.

새 환경을 준비할 때만 스키마 적용 여부를 먼저 확인한 뒤 초기 마이그레이션을 한 번 적용합니다. 관리자 계정은 운영자가 Supabase Auth에서 준비하고, 해당 사용자의 UUID를 `public.portfolio_admins`에 등록합니다. 클라이언트의 프로필이나 metadata 값으로 권한을 부여하지 않습니다. 기존 첫 관리자 부여 SQL의 이메일을 다른 사용자에게 그대로 재사용하지 마세요.

- `portfolio_projects`: 방문자는 공개 사례만 읽을 수 있고 승인된 관리자만 생성·수정·삭제할 수 있습니다.
- `portfolio_admins`: 일반 계정이 스스로 관리자에 등록할 수 없습니다. 운영자가 멤버십을 제거하면 기존 로그인 세션에도 서버의 쓰기·비공개 읽기 권한 제한이 적용됩니다.
- `homepage_hero`: 방문자는 저장된 메인 슬라이드쇼를 읽고 승인된 관리자만 수정할 수 있습니다. 클라이언트의 새 설정 생성·삭제는 허용하지 않습니다.
- `portfolio-images`: 비공개 버킷, WebP만 허용, 저장 파일당 5MB 제한입니다. 방문자는 공개 사례 또는 저장된 메인 슬라이드쇼가 참조하는 사진에 대해 서명 URL을 발급받습니다. 관리자는 미저장 메인 업로드와 비공개 사례 사진도 볼 수 있습니다.
- 파일은 새 UUID 경로로 업로드하며 덮어쓰기를 허용하지 않습니다. 사례나 메인 슬라이드쇼가 참조하는 파일은 삭제할 수 없습니다. 저장 후 사용하지 않는 파일을 별도로 정리합니다.
- 사진 URL의 유효 시간은 600초입니다. 공개 화면은 1분 간격과 focus 시 데이터를 갱신하고, 관리자는 사례 선택 시와 편집 중 4분 간격·focus 시 링크를 갱신합니다.
- 수정과 삭제는 `updated_at` 값을 조건으로 사용합니다. 다른 세션에서 먼저 수정한 기록을 덮어쓰지 않습니다. 사진 링크 갱신은 편집 중인 필드·사진 순서·동시 수정 검사 기준을 보존합니다.

`npm test`는 PGlite의 모의 Auth/Storage 스키마에서 애플리케이션 마이그레이션을 실행해 권한을 확인합니다. 실제 Storage API·이메일·호스팅 동작 검증을 대신하지 않습니다.

## 사진별 편집과 공개 확대보기

사진 JSON에는 `path`, 최대 200자의 `caption`, 최대 2,000자의 선택적 `description`을 저장합니다. 부연설명은 줄바꿈을 보존합니다. 저장 payload와 변경 감지 signature에 부연설명이 포함되며, 사진 순서를 바꿔도 해당 사진의 설명을 함께 이동합니다. 기존 업로드 제한은 사례당 20장, JPEG·PNG·WebP 원본 장당 20MB 이하로 유지합니다.

관리자 `PhotoEditor`는 사진 탭별로 제목과 부연설명을 편집합니다. 공개 상세보기는 ‘사진 설명’과 ‘시공 소개’를 나누고, 사진 클릭 시 `PhotoLightbox`를 표시합니다. 확대보기는 화면 맞춤·100% 저장 픽셀 크기·이전/다음·Escape 닫기를 지원합니다. Escape는 안쪽 확대보기만 닫으며 초점을 사진 버튼으로 돌려줍니다. 100% 상태의 방향키는 스크롤을 위해 유지합니다.

이미지는 업로드 시 긴 변을 최대 2,400px로 줄입니다. 100% 보기는 이 저장 파일을 원래 픽셀 크기로 표시하는 기능이며, 더 높은 업로드 원본 해상도를 복원하거나 별도 원본 파일을 내려받는 기능은 제공하지 않습니다.

사진별 독립 편집과 순서 변경 후 설명 보존을 검증했고, `0.1.1` 공개 사진별 설명·화면 맞춤/100% 확대보기·Escape 및 초점 복귀는 운영 화면에서도 확인했습니다. 재배포 후에도 같은 기능이 유지되는지 확인합니다.

## 메인 슬라이드쇼 설정

`heroModel`은 사진 1~10장, 짧은 제목 `badge` 최대 80자, 필수 사진 문구 `title` 1~200자, `fit`의 `cover`·`contain` 값을 검증합니다. 저장 경로는 기본 사진 4종 또는 `hero/<UUID>.webp`이며 외부 임의 URL과 중복 사진은 클라이언트에서 거부합니다. SQL 003도 사진 수·경로·문구·표시 방식을 검사합니다. 일반 시공 사례의 사진 20장 제한과는 별개입니다.

관리자 `HeroManager`에서 추가·교체·정렬·제거와 문구 편집을 수행하며, 교체할 때에는 해당 항목의 문구와 표시 방식을 유지합니다. JPG·PNG·WebP 원본 장당 20MB 이하를 `prepareImage`로 긴 변 최대 2,400px·WebP·저장 파일 5MB 이하로 처리합니다. 기본 사진은 공개 홈페이지에 포함된 파일을 사용하고, 업로드 사진은 비공개 버킷에서 600초 서명 URL을 발급받습니다. 관리자 CSP에는 기본 사진 미리보기를 위해 `https://designmood.kr` 이미지 출처를 허용합니다.

`saveHero`는 `updated_at` 조건으로 동시 저장을 검사합니다. 4분 간격과 focus 시 사진 URL만 갱신하여 미저장 문구·순서·동시 수정 검사 기준을 유지합니다. 메뉴 이동은 미저장 변경 확인과 중복 전환 잠금을 사용합니다. 폐기 시 저장된 설정으로 먼저 복원한 뒤 미저장 파일을 정리하며, 정리·업로드·저장은 동시에 실행되지 않도록 잠급니다. 저장 전 업로드는 공개 설정에 포함되지 않습니다.

공개 `HeroSection`은 새로 로드할 때, focus 시와 표시 중 60초마다 설정을 다시 확인합니다. 첫 조회 실패 시 기본 사진 4장을 표시하며, 이후 갱신 실패 시 현재 설정을 유지합니다. 슬라이드 수가 줄면 표시 인덱스를 유효 범위로 제한합니다. 긴 제목은 2줄·사진 문구는 3줄로 제한하여 사진 프레임 내에 표시합니다.

`0.1.2` 기준 모델·권한 테스트 20개와 공개·관리자 두 빌드를 통과했습니다. SQL 003 적용과 기본 사진 4장 보존은 확인했지만 새 관리 UI와 공개 화면의 운영 배포 완료를 뜻하지 않습니다. 배포 후 관리자 메뉴·미저장 이동 확인·추가/교체/정렬/저장·다른 창의 저장 충돌과 공개 모바일 화면을 확인합니다.

## 인증 origin과 이메일 복구

Supabase Authentication URL Configuration의 Site URL은 `https://admin.designmood.kr`입니다. 허용 redirect에는 `https://admin.designmood.kr/`와 `https://design-mood-admin-2120.netlify.app/` 두 주소를 등록했습니다. 로컬 복구 검증이 필요하면 `http://localhost:5176/`을 별도로 허용합니다. 운영 설정을 바꿀 때 현재 콘솔과 대조하세요.

복구 이메일 요청은 사용 중인 origin의 `/`로 돌아가도록 지정합니다. 복구 링크로 돌아오면 새 비밀번호 입력 화면을 표시합니다. 비밀번호 최소 길이는 화면에서 12자로 제한합니다. 관리자 세션은 접속 origin의 `sessionStorage`에 저장되므로 Netlify 기본 주소·사용자 지정 주소·로컬 주소 사이에 공유되지 않습니다.

사용자 지정 SMTP는 아직 설정되지 않았습니다. 이메일 요청 성공 응답이나 UI 안내만으로 메일 도착을 보장하지 마세요. 운영자가 SMTP 설정과 발송 제한을 확인하고 실제 관리자 메일함에서 재설정 메일 수신·링크 접속·비밀번호 변경·재로그인을 확인해야 합니다.

## 공개 홈페이지 배포

`.github/workflows/deploy.yml`은 `main` 푸시 또는 수동 실행으로 동작합니다. GitHub 저장소 변수의 URL/key를 사용해 Node.js 24에서 `npm ci`, 연결 설정 검사, `npm test`, `npm run build`를 수행한 뒤 `dist/`를 GitHub Pages로 배포합니다.

배포 후 공개 주소에서 메인 슬라이드쇼 사진·문구·표시 방식·갱신과 모바일 긴 문구 표시를 확인합니다. 사례 목록, 공간 유형 필터, 사진 상세보기, 상담 연결, 평수 슬라이더와 약도도 확인합니다. 테스트용 현장과 개인정보가 공개되지 않았는지도 확인합니다. 빌드 성공은 사용자 화면과 실제 데이터 연결 검증을 대신하지 않습니다.

## 관리자 Netlify 배포

```powershell
npm run build:admin
```

기존 Netlify 사이트 ID `78df4310-8146-4fc9-a663-64b9f1aafbb1`의 수동 배포 영역에 `dist-admin/`을 올립니다. 새 사이트를 만들지 않습니다. `netlify.toml`에도 같은 빌드 명령과 출력 폴더가 정의되어 있지만, 현재 운영 경로는 미리 빌드한 폴더를 올리는 Netlify Drop 수동 배포입니다.

`dist-admin/_headers`는 `no-store`, `noindex,nofollow`, 프레임 차단, 콘텐츠 유형 보호와 CSP를 포함합니다. 배포 응답에서 헤더 적용을 확인하고, 관리자 로그인·비공개 저장·사진 업로드·공개 전환·사진 정렬·동시 수정 충돌을 실제 서비스에서 확인합니다. 메인 슬라이드쇼 메뉴에서도 기본 사진 미리보기·미저장 이동 확인·사진과 문구 저장을 확인합니다. 관리자 빌드를 공개 홈페이지의 `dist/` 대신 올리지 않도록 주의합니다.

## 관리자 도메인 연결

카페24에 등록했고 권한 있는 네임서버 응답으로 확인한 DNS 레코드입니다. 기존 루트·www·와일드카드 레코드는 유지했습니다. 동일 레코드를 중복으로 만들지 마세요.

| 유형 | 호스트 | 값 |
| --- | --- | --- |
| CNAME | `admin` | `design-mood-admin-2120.netlify.app` |
| TXT | `subdomain-owner-verification` | `6c561260f6821e8767a9badc782fce34` |

도메인 소유권·DNS 검증과 HTTPS 정상 응답을 확인했습니다. 사용자 지정 주소에서 로그인 화면을 확인했고, Netlify 기본 운영 주소에서는 실제 관리자 로그인·비공개 저장·사진 2장 표시·검증 사례 삭제까지 확인했습니다. 두 origin의 로그인 세션은 공유되지 않습니다. 사용자 지정 SMTP 및 비밀번호 재설정 이메일 수신은 아직 검증하지 않았습니다.
